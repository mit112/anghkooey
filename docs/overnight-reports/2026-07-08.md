## 5. Operational notes for the next session (READ FIRST)
- **iCloud `~/Documents` hazard (recurring):** the repo spawns ` 2.swift` / ` 2.xcodeproj` / `Info 2.plist` conflict duplicates and stale `.build` caches. These break builds (`invalid redeclaration`, `PCH ... module cache path`, `missing SwiftShims`) and the test-dir glob. **Fix before debugging any build failure:** `rm` the untracked ` 2.*` files and `rm -rf Packages/*/.build .ci-derived-data`. (4 stray ` 2` files were removed this session; none were ever committed.) Saved as memory `anghkooey-icloud-build-hazard`.
- **`make generate` drops `NSCameraUsageDescription` + `LSSupportsOpeningDocumentsInPlace` from `App/Anghkooey/Info.plist`** — `App/project.yml`'s `info.properties` omits them, so regenerating clobbers the hand-maintained keys (camera crash / ITMS on upload). **This is exactly #56's job.** Until #56: after any `make generate`, restore Info.plist (`git checkout App/Anghkooey/Info.plist`) or re-add the two keys. New app-target test files were wired into `project.pbxproj` by hand (4 lines each) to avoid running `make generate`.
- **SourceKit live diagnostics are unreliable in this repo** — "No such module 'Testing'/'AnghkooeyCore'/'UIKit'", "Cannot find type ErrorPresenter", "nonisolated(unsafe) has no effect" are all FALSE positives. Trust green `xcodebuild`/`ci.sh` over SourceKit. (`@Observable` stored `Task?` properties genuinely require `nonisolated(unsafe)`.)
- **`ci.sh` uses `xcodebuild` on the iPhone 17 Pro simulator**, not `swift build`/`swift test` (plain `swift build` fails on iOS-only SwiftUI APIs — ignore it).
- **Gate/continuation-based tests need a registration barrier** (`await waitUntil { gate.callCount >= 1 }`) between multiple `present`/`apply` calls before firing a continuation, or the unstructured Tasks race (fixed one such flake in #70).
