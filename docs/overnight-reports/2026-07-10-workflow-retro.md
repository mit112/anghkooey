# Workflow-retro delta — session 3 (2026-07-10)

Did the session-2 §6 efficiency changes actually lower $/PR? Short answer: **the process changes helped and were adopted cleanly; the dominant cost/risk this session was environmental (iCloud), not workflow.** Deltas vs the 2026-07-09 retro:

## What the §6 changes bought (kept — they worked)
- **Content-addressed CI gate (tree-hash proof).** Verifying that an integration tip / committed tree was byte-identical to the last green-gated PR tree let me **skip a redundant full `ci.sh` on every merge-to-integration and both main promotions** (PR #87, #93, #95, and each per-issue integration merge). That's ~6–8 avoided full xcodebuild cycles (each ~6–8 min). This is the single most effective adopted change. When I DID edit a tree post-gate (applying review findings on #41/#53/#48), I re-ran the authoritative `ci.sh` — correctly, not reflexively.
- **Subagent skill-loading → zero round-2s.** Every execution subagent was told to load the matching ECC Swift skill (swiftui-patterns/make-interfaces-feel-better for UI, swift-actor-persistence for CardStore, protocol-di-testing for seams). Result: **0 round-2 subagent dispatches this session** (session 2 needed a 150K-tok #29 round-2). Findings were small enough to apply via orchestrator Edit. Measurable win.
- **Review-by-touched-surface, not diff size.** #41 (CardStore, central) got full swift-reviewer + silent-failure-hunter; #53 (swipe-commit state machine, GPT-flagged not-leaf) got full swift-reviewer; #39/#40/#54 + #48's leaf parts got orchestrator self-review. The #53 reviewer caught a real anti-drift MAJOR (duplicated eligibility logic) — vindicating "don't downgrade state-machine diffs."
- **Fixed-schema subagent reports + CI-log-to-file.** Reports stayed on the schema; full CI logs went to file paths (pasted tail only on failure). Kept orchestrator context leaner than session 2's prose reports.
- **GPT-5.5 checkpoints, again highest-ROI.** T1 cross-issue checkpoint caught the `submitEdit` pre-canonicalization tag-casing echo (→ PR #92); the #48 checkpoint found a pre-existing double-unfreeze reentrancy (→ filed #96). Keep unconditionally.
- **Per-tier main promotion (authorized).** Kept the integration branch bounded (0-ahead after each promotion) instead of the 48-commit balloon.

## What DIDN'T pay off / regressed
- **The one-time setup skills were low-value here.** `/harness-audit` scored 17/39 but its low categories (Quality Gates "add test script", Eval Coverage "add evals/", Security Guardrails "add hooks.json") are **JS-repo-shaped and structurally inapplicable to a Swift/xcodebuild project** — tests exist and run via `ci.sh`, guardrails are intentionally minimal. `/fewer-permission-prompts` found **nothing to add** (all frequent calls are auto-allowed reads or mutations/exec that must not be blanket-allowed). Net: ~2 setup steps for ~0 actionable output. Next time, skip or run only if the harness is genuinely misconfigured.
- **The config knobs (MAX_THINKING_TOKENS=10000, CLAUDE_AUTOCOMPACT_PCT_OVERRIDE=50, ECC_HOOK_PROFILE=minimal) were written to `settings.local.json` MID-SESSION and almost certainly did NOT take effect** (the harness reads env at process start). To actually cap the §5.1 orchestrator-context cost, they must be set **before launching** the session.
- **The mechanical per-tier context reset stayed theoretical.** I hit clean tier boundaries (backlog→main, T1→main) but could not self-restart the orchestrator context; StrategicCompact/autocompact did not fire. The single long Opus context is still the #1 structural cost (the retro's own finding). The `scratchpad/EXECUTION-LEDGER.md` carried crash-recovery state well, but that addresses recovery, not cost. **Only the harness can realize the reset** — recommend the launcher restart the context per tier (feeding the report + memory + ledger).

## The dominant cost/risk this session: the iCloud environment
Not a workflow issue, but it ate the most time and nearly derailed the run:
- Baseline `ci.sh` failed **three times** before going green: a corrupt `.build/build.db`, then `error: input file … was modified during the build` (iCloud re-syncing source files mid-compile), resolved only by force-materializing the tree (`git ls-files | xargs cat`) — which then made `brctl download` pull down **conflict-copy dups** (`* 2.swift`) that caused `invalid redeclaration`.
- Mid-way through the main promotion, a `git` **SIGBUS** + eviction of top-level tracked files (`.gitignore`, `CLAUDE.md`, …) in real time proved the `~/Documents` working copy was unusable.
- **Fix: pivoted all work to a fresh clone at `/private/tmp/anhkhooey-work` (outside iCloud) — stable for the entire rest of the session.** Recommendation: **make a non-iCloud clone the default working copy**, and move the canonical repo out of `~/Documents`. The dup-sweep is a band-aid; the clone/relocation is the fix.
