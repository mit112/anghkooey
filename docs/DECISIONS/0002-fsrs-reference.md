# 0002 — FSRS-6 Reference Implementation

**Date:** 2026-05-20
**Status:** Accepted
**Supersedes:** §4.1 of `docs/superpowers/plans/2026-05-20-rewind-implementation-plan.md` (default `open-spaced-repetition/rs-fsrs`)

---

## Context

`foundation.md §9.3` requires the Swift FSRS-6 implementation to pass a parity test suite against a reference implementation. The strategic plan defaulted to `open-spaced-repetition/rs-fsrs`, but that default was written before today's verification. M1 task T2 requires pinning a specific commit so the parity fixtures are reproducible.

Two candidates were evaluated:

| | `open-spaced-repetition/rs-fsrs` | `open-spaced-repetition/ts-fsrs` |
|---|---|---|
| License | MIT | MIT |
| Latest release | v1.2.1 (2024-10-28) | v5.4.0 (2026-05-18) |
| Latest algorithm | FSRS-5 (v1.0.0 release notes) | FSRS-6.0 (`FSRSVersion` constant) |
| Default parameter count | 19 (FSRS-5) | 21 (FSRS-6) |
| Active development | Quiet since Oct 2024 | Active (274 commits, monorepo) |
| Determinism control | `enable_fuzz` flag | `enable_fuzz` flag |
| Driveability from a script | `cargo run` + small Rust harness | `node` ESM script (Node 20 preinstalled on dev box) |

`rs-fsrs` has not shipped FSRS-6. Its `master` branch is FSRS-5 at v1.2.1. There is no v2.x branch and no FSRS-6 issue/PR resolving the gap. The strategic plan's preference for `rs-fsrs` predates this check; with FSRS-6 unavailable there, the choice collapses to `ts-fsrs`.

---

## Decision

The FSRS-6 reference implementation for the parity harness is **`open-spaced-repetition/ts-fsrs` at tag `v5.4.0`**, commit SHA **`80bab011a7f496b06c99924d54e772cf258244f2`**.

Verified at this SHA:

- `packages/fsrs/src/constant.ts` declares `FSRSVersion = "v{version} using FSRS-6.0"` and `default_w` of length 21.
- `packages/fsrs/src/default.ts → checkParameters` enforces parameter length ∈ {17, 19, 21} mapped to FSRS-v4, v5, v6.
- `Rating` enum: `Again=1, Hard=2, Good=3, Easy=4` (matches `AnghkooeyCore.Rating`).
- `State` enum: `New=0, Learning=1, Review=2, Relearning=3` (matches `AnghkooeyCore.CardState`).

### Pinned default parameters (21-weight FSRS-6.0)

These are the constants the Swift port reproduces verbatim in T3 (`FSRSParameters.default`):

```
w = [
  0.212, 1.2931, 2.3065, 8.2956, 6.4133, 0.8334, 3.0194, 0.001,
  1.8722, 0.1666, 0.796, 1.4835, 0.0614, 0.2629, 1.6483, 0.6014,
  1.8729, 0.5425, 0.0912, 0.0658, 0.1542,
]
request_retention      = 0.9
maximum_interval       = 36500   // days
enable_fuzz            = false   // determinism required for parity
enable_short_term      = true
learning_steps         = ["1m", "10m"]
relearning_steps       = ["10m"]
```

`w[20] = 0.1542` is `FSRS6_DEFAULT_DECAY`.

### Parity epsilon

Per `docs/superpowers/plans/2026-05-20-rewind-implementation-plan.md §4.1`, doubles match within **1e-9** absolute, integers (`scheduled_days`, `reps`, `lapses`, `learning_steps`, `state`) match exactly. `due` is recorded as a per-step offset in **seconds** from the fixture epoch; the Swift harness compares within ±1 second to absorb sub-second rounding differences between `Date` and JS `Date`.

### Coverage requirements

- **50 synthetic fixtures**, hand-shaped to exercise:
  - Graduation paths from `New` (Again/Hard/Good/Easy as first rating)
  - Multi-step `Learning` chains and short-term mode interactions
  - First-time entry into `Review` state
  - Multiple `Review`→`Review` steps with varying elapsed gaps
  - `Review`→`Relearning` lapse and `Relearning`→`Review` recovery
  - Very-overdue cards (elapsed ≫ scheduled_days)
  - Multi-lapse sequences
- **100 deterministic-random fixtures**, seeds `0..99` of a mulberry32 PRNG (recorded in `seed`). Each draws sequence length 3..12, ratings uniformly from {1..4}, and elapsed seconds from a log-uniform mix spanning [60s, 365d].

Total: **150 fixtures**.

### Regeneration

```
cd scripts/fsrs
npm ci
node generate-parity-fixtures.mjs
```

Output path is hard-coded relative to the repo root. The script asserts the resolved `ts-fsrs` package version equals the pinned tag.

## Consequences

- **Positive:** FSRS-6 with current 21-weight defaults; actively maintained upstream; trivial-to-drive from a Node script already available on the dev machine.
- **Drift risk:** `ts-fsrs` ships fast. Pinning a commit (not just a tag) means we are immune to retroactive tag movement, but the JS implementation could still diverge from the Open Spaced Repetition canonical math. Mitigation: when a divergence is suspected, cross-check the suspect formula against `open-spaced-repetition/fsrs-rs` (Rust, different repo from `rs-fsrs`) or the FSRS-6 spec paper before changing the Swift port.
- **Updating the reference:** any move off `v5.4.0` requires a new ADR (`0003-…`), full fixture regeneration, and a re-run of the parity harness on the existing Swift port. The fixture file's `source.commit` field is the single source of truth — divergence between it and `package-lock.json` is a CI fail.
- **No production dependency on ts-fsrs.** The reference implementation is a *test-time tool*, never imported by the app. The Swift port is the production code path.
