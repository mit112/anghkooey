## Lane breakdown

Lanes are sized so each ends in a green test suite and a PR-able diff. Dependencies are honest, not invented.

### Lane C — Cushion Mode + Freeze (small, independent)
**Why first:** Smallest surface; no dependency on grade-system rework; lands two named foundation features quickly; produces a Settings surface that later lanes can reuse.
**Detailed plan:** `2026-05-22-m5.5c-cushion-freeze.md` (this commit).

### Lane G — 4-grade rating system (foundational refactor)
**Why second:** Every other UX lane lands on this substrate. Doing it second (after Lane C settles) avoids merging UX work that we'll throw away.
**Scope:** Replace `ReviewGrade { missed, gotIt }` with `ReviewGrade { again, hard, good, easy }`. Wire the 4 paths through `ReviewSession.submit`, `CardStore.apply` (uses `Rating` enum which already has 4 cases — no scheduler change), `MockCardStore`, all tests, and a 4-button `ReviewView`. Migration of in-flight grade enum needs a friendly compile-time guard (deprecate-and-remove, not silent rename).
**Detailed plan:** `2026-05-22-m5.5g-four-grade-rating.md` (write at lane entry).

### Lane S — Swipe-to-grade + edit-before-accept (UX on Lane G substrate)
**Why third:** Depends on Lane G (the 4 grades must exist before swipe directions can map to them). Edit-before-accept is bundled here because both touch `CardReviewSheet` / `ReviewView` gesture layers.
**Scope:** Card-stack swipe gestures (`DragGesture`) with thresholds: left→Again, right→Good, up→Easy, down→edit. Edit sheet: tap-to-edit question/answer/tags, Save commits to `CardStore.update`, Cancel keeps original. `CardStore.update(id:question:answer:tags:)` if not already present.
**Detailed plan:** `2026-05-22-m5.5s-swipe-and-edit.md` (write at lane entry).

### Lane T — Tags UI + Library surface (new tab)
**Why fourth:** Substantial new view code; needs Lane G/S done so the Library row → tap-to-edit flow uses the final edit sheet. Tags are already stored on `CardDraft` (`proposedTags`); plumbing to `Card` and UI is the missing piece.
**Scope:** Extend `Card` schema (V3) with `tags: [String]`; migration. New `Library` tab with cards-list, tap-row → edit sheet, filter chips by tag. Tag picker in edit sheet. AI's `proposedTags` honored on accept.
**Detailed plan:** `2026-05-22-m5.5t-tags-and-library.md` (write at lane entry).

### Lane M — Mnemonic button (small finisher)
**Why last:** Smallest UX surface; pure additive; depends on the edit sheet from Lane S to host the button. Single FoundationModels prompt + a button in the card view.
**Scope:** `MnemonicService` protocol + `LiveMnemonicService` using `LanguageModelSession`. Button in card detail view → calls service → shows mnemonic text inline. Mnemonic stored on `Card` (V3 or V4 — fold into V3 if Lane T is recent).
**Detailed plan:** `2026-05-22-m5.5m-mnemonic-button.md` (write at lane entry).
