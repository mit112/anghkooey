# Anghkooey v1.1 — Feature Set Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Anghkooey v1.1 — five independent feature lanes that close the four remaining 2026 iOS skill gaps (#2 AppIntents/Siri, #3 WidgetKit interactive, #4 CloudKit sync) and add a non-gamified knowledge metric, on top of the feature-complete v1 (TestFlight build 1).

**Architecture:** Lane-based milestone in the M5.5 style. Each lane is one feature that ends in a green `xcodebuild test` run and a PR-able diff. Lanes are ordered smallest-surface-first so the App Group / entitlement understanding compounds before the high-risk lanes (Widget, CloudKit). All new service boundaries follow the project's protocol + production + mock pattern. Codex is leveraged contract-first: Claude authors failing Swift Testing tests + API skeletons, Codex makes them pass, Claude verifies locally via `xcodebuild` (Codex sandbox cannot run it).

**Tech Stack:** Swift 6 strict concurrency, SwiftUI, SwiftData, AppIntents, WidgetKit (interactive, iOS 17+ App Intent buttons), CloudKit private DB via SwiftData `ModelConfiguration(cloudKitDatabase:)`, App Group `group.com.mitsheth.anghkooey`, FoundationModels (already integrated), Swift Testing.

---

## Why this project exists (brief)

Per `CLAUDE.md`: Anghkooey is both a real product and a deliberate portfolio piece closing specific 2026 iOS skill gaps. v1 (M1–M6) shipped the capture → on-device AI authoring → accept → grace-first review loop and went to TestFlight. v1.1 spends the remaining "designed-for-from-day-one" seams: AppIntents (gap #2), WidgetKit interactive (gap #3), and CloudKit private-DB sync (gap #4). Lane K adds a product-level expression of the anti-shame philosophy — measure knowledge built, not streaks. Every lane defends at least one skill gap or the product wedge; none is AI hype or scope-creep into watchOS/visionOS (those belong to Projects B/C).

## Current-state facts the lanes build on (verified against shipped code)

- **`Card.Snapshot`** (`Packages/AnghkooeyCore/.../Persistence/CardStore.swift`) already carries `stability: Double`, `tags: [String]`, `mnemonic: String?`. FSRS-6 `stability` is in **days** (confirmed in `LiveFSRS6Engine.swift` — interval = `stability × intervalModifier`). Lane K's "≥ 21 days" threshold = `stability >= 21`.
- **`CardStoreProtocol`** has: `create`, `dueCards(asOf:)`, `apply(_:to:grade:now:)`, `count(asOf:)`, `shiftAllDueDates(byDays:)`, `allCards()`, `update(id:question:answer:tags:)`, `updateMnemonic(id:mnemonic:)`. `MockCardStore` mirrors all of them.
- **App Group** `group.com.mitsheth.anghkooey` is provisioned in `App/Anghkooey/Anghkooey.entitlements` and `App/AnghkooeyShare/AnghkooeyShare.entitlements`. The inbox contract (`InboxConstants`, `InboxWriter`, `InboxDrainer`, Darwin notification `com.mitsheth.anghkooey.inboxDidChange`) is the established cross-process pattern.
- **`InboxWriter.write(text:sourceApp:)`** is the existing path text takes into the app. AppState drains via `InboxNotifier` on foreground. Lane I and Lane W both write to this inbox rather than inventing a new channel — except Lane W also needs a *grade* channel back (new).
- **`AppState`** (`@MainActor @Observable`) owns the drain pipeline and the accept-sheet queue; `cardStore` is injected. `AnghkooeyApp.init()` currently builds the production `ModelContainer` **inline** with `Schema(AnghkooeySchemaV1.models)` and **no migration plan** — Lane C2 must route it through `AnghkooeyModelContainer` (which already uses `AnghkooeySchemaV3` + `AnghkooeyMigrationPlan`). This is a latent bug Lane C2 fixes as a precondition.
- **`AnghkooeyModelContainer.makeInMemoryContainer()`** is the factory. It uses `Schema(versionedSchema: AnghkooeySchemaV3.self)` + `AnghkooeyMigrationPlan`. Lane C2 adds a parallel on-disk + CloudKit factory method here.
- **`ReviewSession`** (`AnghkooeyUI`) already exposes Cushion fields and `submit(grade:)`. Lane W's reconciliation reuses the same `scheduler.next` + `store.apply` path.
- **xcprivacy fragility:** after every `make generate`, grep `PrivacyInfo` count in `App/Anghkooey.xcodeproj/project.pbxproj`. Was 4 in `project.yml` comments but M6 raised the expected count to **6** (two targets). Lane W adds a **third** target (the widget extension) → expected count rises to **9** after Lane W. Each lane that runs `make generate` must re-verify and re-patch.
- **`sed` is aliased to `sd`.** Never `sed -i`. Use Python line-by-line for in-place edits to `project.pbxproj` / `project.yml`.

## Lane breakdown

Lanes are sized so each ends in a green suite and a PR-able diff. Order is smallest-surface / lowest-risk first.

### Lane K — Cumulative LTM metric
**Why first:** Smallest surface, zero new dependencies, purely additive, no entitlement or target changes. Closes the "no gamification" gap with almost no risk and warms up the suite.
**Scope:** A pure, testable aggregation `longTermMemoryCount(asOf:)` on `CardStoreProtocol` (default-implementable from `allCards()`, but given a dedicated `fetchCount` predicate path on the actor for performance). A card counts once `stability >= ltmThresholdDays` (default 21). Surface the number on the Review screen header as "N committed to long-term memory" and add a read-only row in Settings. No streak, no daily delta, no shame framing.
**Codex role:** **Reviewer (single pass)** on the aggregation predicate + threshold boundary (is it `>=` or `>`? does a brand-new card with `stability == 0` ever count? does Cushion Mode affect the metric? — it must not). 10-min timeout; fall back to `ecc:code-reviewer`.

### Lane A — Ambient clipboard capture
**Why second:** Still small, no new entitlements, extends the existing capture flow by reusing `AppState.enqueue` and the accept sheet. No new persistence.
**Scope:** A `ClipboardOffer` value type + `ClipboardCaptureCoordinator` (`@MainActor @Observable`) that, on app foreground, inspects `UIPasteboard.general` for plain text ≥ 20 chars not previously offered. Dedup by SHA-256 of normalized text, persisting offered-hashes (capped FIFO ring of 50) in `UserDefaults`. On a fresh hit it sets a published `pendingOffer`; the UI renders a non-intrusive banner ("Create cards from clipboard?"). Tapping routes the text through `AppState.enqueue(resolvedText:)` (same path as Share Sheet / OCR), which produces a draft and shows the existing accept sheet. **Never auto-inserts cards.** Dismiss marks the hash offered.
**Codex role:** **Primary implementer (contract-first).** Claude writes failing tests for `ClipboardCaptureCoordinator` (dedup, ≥20-char gate, ring eviction, offer→route) + the protocol/skeleton; Codex implements the bodies. Claude runs `xcodebuild test` to verify.

### Lane I — AppIntents + Siri capture
**Why third:** High portfolio signal (skill gap #2, demand 5/5). Reuses the App Group inbox + `InboxWriter` already built in M3 — the hard cross-process part is done. No new entitlements (App Group already present; AppIntents needs none).
**Scope:** An `AddToAnghkooeyIntent: AppIntent` in the app target accepting a `@Parameter` text string, writing it via `InboxWriter.write(text:sourceApp:"siri")` to the shared App Group inbox so the next foreground drain authors it (identical to Share Sheet behavior). An `AppShortcutsProvider` donates the phrase "add to Anghkooey" to Siri/Spotlight. The intent returns a confirmation dialog. Because `InboxWriter` is in `AnghkooeyCore` and the intent runs in the app process, the intent constructs an `InboxWriter` against the App Group container URL directly.
**Codex role:** **Primary implementer** of the `AppIntent` + `AppShortcutsProvider` conformance boilerplate (these are highly templated). Claude writes a failing test that exercises the intent's `perform()` against a temp-dir `InboxWriter` and asserts a JSON item lands; Codex fills the conformance. Claude verifies on device that Siri donation surfaces (manual step).

### Lane W — WidgetKit interactive (2-button review widget)
**Why fourth:** Highest-complexity lane; depends on the App Group patterns being well-understood (reinforced by Lane I) because it adds a *new* cross-process channel (grade decisions flowing widget → app). Adds a third build target. High portfolio signal (skill gap #3).
**Scope:** A new `AnghkooeyWidget` app-extension target. A `TimelineProvider` reads the single most-due card from a shared App Group snapshot file (`widget/due-snapshot.json`, written by the app on foreground/after-review). The widget shows the question and two interactive buttons ("Again", "Good") implemented as `AppIntent`s (`GradeCardIntent`) that **do not** open the app: they append a grade decision to a shared App Group queue file (`widget/grades.jsonl`) and reload the timeline to advance to the next card locally. The main app, on next foreground, drains `grades.jsonl`, replays each decision through `scheduler.next` + `store.apply`, then rewrites the due-snapshot. **The widget never touches SwiftData directly** — it only reads/writes the two App Group JSON files. Reconciliation is idempotent (each grade carries a UUID; replayed grades are deduped).
**Codex role:** **Primary implementer** of the WidgetKit entry point (`Widget`, `TimelineProvider`, `AppIntentConfiguration`, the SwiftUI widget view) — heavily templated boilerplate. **Reviewer (separate pass)** on the grade-reconciliation logic in the app (idempotency, replay ordering, snapshot rewrite). Reconciliation *implementation* stays with Claude (state-mutation hazard). Two Codex dispatches: one impl, one review.

### Lane C2 — CloudKit private DB sync
**Why last:** Highest risk — requires a CloudKit container provisioned in the Apple Developer portal, the `iCloud` + CloudKit entitlement, and the `aps-environment` push entitlement for sync notifications. Largest blast radius (touches the production `ModelContainer`). But the schema was designed for it (all V2/V3 added fields are Optional, no custom store), so the code change is mostly wiring + a precondition fix.
**Scope:** (1) Fix `AnghkooeyApp.init()` to build its container through `AnghkooeyModelContainer` (currently inline with V1 schema + no migration plan — a latent migration bug). (2) Add `AnghkooeyModelContainer.makeContainer(syncMode:)` taking a `SyncMode` enum (`.local` / `.cloudKit`); `.cloudKit` sets `ModelConfiguration(..., cloudKitDatabase: .private("iCloud.com.mitsheth.anghkooey"))`. (3) Add the `iCloud` (CloudKit) + `aps-environment` entitlements to `Anghkooey.entitlements` and the container ID to `project.yml` as a documented constant. (4) A Settings toggle bound to a `UserDefaults`-backed `SyncPreference`; flipping it requires an app relaunch (documented in copy) because `ModelContainer` is constructed once at launch. (5) Document the container ID and the "every CloudKit field must be Optional or have a default" invariant in `ARCHITECTURE.md`.
**Codex role:** **Reviewer only** on the migration-safe `makeContainer(syncMode:)` change (does `.cloudKit` keep the same `AnghkooeyMigrationPlan`? are all model fields CloudKit-legal — Optional or defaulted? is the relationship inverse correct for CloudKit, which forbids `@Attribute(.unique)`?). Implementation stays with Claude — CloudKit provisioning/entitlement errors need build feedback Codex's sandbox can't provide.

import Foundation

/// Cumulative long-term-memory metric configuration.
///
/// A card is considered "committed to long-term memory" once its FSRS-6
/// `stability` (which is measured in days — the interval at which recall
/// probability decays to the target retention) crosses `thresholdDays`.
/// Default 21 days ≈ "will probably remember this in 3 weeks".
///
/// This metric is deliberately the *opposite* of a streak: it counts
/// knowledge built, never punishes a gap, and is independent of whether a
/// card is currently due. See `foundation.md` §3 principle 3 ("Grace over
/// guilt. No streaks.").
public enum LTMConfig {

    /// Default stability threshold in days.
    public static let defaultThresholdDays: Double = 21

    /// Counts snapshots whose `stability` is at or above `thresholdDays`.
    /// Pure and synchronous so callers and tests can reason about it directly.
    public static func count(
        _ cards: [Card.Snapshot],
        thresholdDays: Double = defaultThresholdDays
    ) -> Int {
        cards.lazy.filter { $0.stability >= thresholdDays }.count
    }
}
```

import Foundation

/// The single due card the widget displays. Written by the app, read by the
/// widget's TimelineProvider. Sendable value type — no SwiftData crosses here.
public struct WidgetDueSnapshot: Codable, Equatable, Sendable {
    public let cardID: UUID
    public let question: String
    public let dueCount: Int
    public init(cardID: UUID, question: String, dueCount: Int) {
        self.cardID = cardID
        self.question = question
        self.dueCount = dueCount
    }
}

/// A grade decision made in the widget, queued for the app to replay. Carries
/// a stable `id` so replay is idempotent (deduped on reconciliation).
public struct WidgetGradeDecision: Codable, Equatable, Sendable {
    public let id: UUID
    public let cardID: UUID
    public let rating: Rating
    public let decidedAt: Date
    public init(id: UUID, cardID: UUID, rating: Rating, decidedAt: Date) {
        self.id = id
        self.cardID = cardID
        self.rating = rating
        self.decidedAt = decidedAt
    }
}

/// Reads/writes the two shared App Group files that connect the widget and app.
/// The widget never touches SwiftData; it only reads `due-snapshot.json` and
/// appends to `grades.jsonl`. The app reconciles `grades.jsonl` on foreground.
public struct WidgetBridge: Sendable {

    private let containerURL: URL
    public init(containerURL: URL) { self.containerURL = containerURL }

    private var widgetDir: URL { containerURL.appendingPathComponent("widget", isDirectory: true) }
    private var snapshotURL: URL { widgetDir.appendingPathComponent("due-snapshot.json") }
    private var gradesURL: URL { widgetDir.appendingPathComponent("grades.jsonl") }

    private static let encoder: JSONEncoder = {
        let e = JSONEncoder(); e.dateEncodingStrategy = .iso8601; return e
    }()
    private static let decoder: JSONDecoder = {
        let d = JSONDecoder(); d.dateDecodingStrategy = .iso8601; return d
    }()

    private func ensureDir() throws {
        try FileManager.default.createDirectory(at: widgetDir, withIntermediateDirectories: true)
    }

    public func writeSnapshot(_ snapshot: WidgetDueSnapshot) throws {
        try ensureDir()
        let data = try Self.encoder.encode(snapshot)
        let tmp = snapshotURL.appendingPathExtension("tmp")
        try data.write(to: tmp)
        _ = try? FileManager.default.removeItem(at: snapshotURL)
        try FileManager.default.moveItem(at: tmp, to: snapshotURL)
    }

    public func readSnapshot() -> WidgetDueSnapshot? {
        guard let data = try? Data(contentsOf: snapshotURL) else { return nil }
        return try? Self.decoder.decode(WidgetDueSnapshot.self, from: data)
    }

    public func clearSnapshot() throws {
        _ = try? FileManager.default.removeItem(at: snapshotURL)
    }

    /// Appends one decision as a JSON line. Append-only to survive concurrent
    /// widget writes between app reconciliations.
    public func appendGrade(_ decision: WidgetGradeDecision) throws {
        try ensureDir()
        let line = try Self.encoder.encode(decision)
        if let handle = try? FileHandle(forWritingTo: gradesURL) {
            defer { try? handle.close() }
            try handle.seekToEnd()
            try handle.write(contentsOf: line)
            try handle.write(contentsOf: Data("\n".utf8))
        } else {
            var blob = line; blob.append(Data("\n".utf8))
            try blob.write(to: gradesURL)
        }
    }

    public func readGrades() -> [WidgetGradeDecision] {
        guard let data = try? Data(contentsOf: gradesURL),
              let text = String(data: data, encoding: .utf8) else { return [] }
        return text.split(separator: "\n").compactMap { line in
            guard let lineData = line.data(using: .utf8) else { return nil }
            return try? Self.decoder.decode(WidgetGradeDecision.self, from: lineData)
        }
    }

    public func clearGrades() throws {
        _ = try? FileManager.default.removeItem(at: gradesURL)
    }
}
```

Per memory `feedback-iso8601-roundtrip-dates`, tests use integer-second `Date(timeIntervalSinceReferenceDate:)` values so the round-trip is exact. `Rating` is already `Codable` in `AnghkooeyCore` (verify; if not, add `Codable` conformance in this commit).

Create `App/Anghkooey/WidgetGradeReconciler.swift`:

```swift
import Foundation
import AnghkooeyCore

/// Replays widget grade decisions into the store on app foreground.
///
/// Idempotent: each decision carries a UUID; once applied, its id is recorded
/// so a duplicated queue line (e.g. the widget appended twice before the app
/// drained) is not double-counted. Unknown cards are dropped. After a
/// successful pass the grade queue is cleared and the due snapshot rewritten.
@MainActor
final class WidgetGradeReconciler {

    private let store: any CardStoreProtocol
    private let scheduler: any FSRS6Engine
    private let bridge: WidgetBridge
    private var appliedIDs: Set<UUID> = []

    init(store: any CardStoreProtocol, scheduler: any FSRS6Engine, bridge: WidgetBridge) {
        self.store = store
        self.scheduler = scheduler
        self.bridge = bridge
    }

    func reconcile(now: Date = .now) async throws {
        let decisions = bridge.readGrades().sorted { $0.decidedAt < $1.decidedAt }
        let due = try await store.dueCards(asOf: now)
        let dueByID = Dictionary(uniqueKeysWithValues: due.map { ($0.id, $0) })

        for decision in decisions {
            guard !appliedIDs.contains(decision.id) else { continue }
            appliedIDs.insert(decision.id)
            guard let snapshot = dueByID[decision.cardID] else { continue } // unknown/not-due: drop
            do {
                let output = try scheduler.next(card: snapshot.schedulingCard, rating: decision.rating, now: decision.decidedAt)
                try await store.apply(output, to: decision.cardID, grade: decision.rating, now: decision.decidedAt)
            } catch {
                // Non-fatal: skip this decision, keep reconciling the rest.
            }
        }
        try bridge.clearGrades()
        try await rewriteSnapshot(now: now)
    }

    /// Writes the current most-due card to the widget snapshot, or clears it if
    /// the queue is empty.
    func rewriteSnapshot(now: Date = .now) async throws {
        let due = try await store.dueCards(asOf: now)
        if let first = due.first {
            try bridge.writeSnapshot(WidgetDueSnapshot(cardID: first.id, question: first.question, dueCount: due.count))
        } else {
            try bridge.clearSnapshot()
        }
    }
}
```

    /// container identifier (`iCloud.com.mitsheth.anghkooey`).

Add to the `AnghkooeyModelContainer` enum:

```swift
    /// The production CloudKit container identifier. Mirrors the value in
    /// `App/project.yml` and the iCloud entitlement. See ADR-0011.
    public static let cloudKitContainerID = "iCloud.com.mitsheth.anghkooey"

    /// Builds the production container for the given sync mode.
    ///
    /// `.cloudKit` requires the iCloud + CloudKit entitlement and a provisioned
    /// container; it will throw at launch if those are absent. Both modes use
    /// the same `AnghkooeySchemaV3` + `AnghkooeyMigrationPlan`, so flipping the
    /// toggle never changes the schema — only the storage backend.
    ///
    /// - Parameter url: Optional explicit store URL (tests). When nil, SwiftData
    ///   uses its default Application Support location.
    public static func makeContainer(syncMode: SyncMode, url: URL? = nil) throws -> ModelContainer {
        let schema = Schema(versionedSchema: AnghkooeySchemaV3.self)
        let configuration: ModelConfiguration
        switch syncMode {
        case .local:
            configuration = url.map { ModelConfiguration(schema: schema, url: $0) }
                ?? ModelConfiguration(schema: schema)
        case .cloudKit(let containerID):
            configuration = ModelConfiguration(
                schema: schema,
                cloudKitDatabase: .private(containerID)
            )
        }
        do {
            let container = try ModelContainer(
                for: schema,
                migrationPlan: AnghkooeyMigrationPlan.self,
                configurations: [configuration]
            )
            CoreLog.persistence.debug("ModelContainer created (syncMode: \(String(describing: syncMode), privacy: .public))")
            return container
        } catch {
            CoreLog.persistence.error("ModelContainer init failed: \(error.localizedDescription, privacy: .public)")
            throw PersistenceError.containerCreationFailed(underlying: error)
        }
    }
```

> **CloudKit-legal-schema note (Opus design decision):** `Card.id` is `@Attribute(.unique)`. CloudKit silently ignores `.unique`; SwiftData tolerates this (it drops the constraint under CloudKit). All V2/V3 added fields are already Optional. The `@Relationship` to `ReviewLog` has an inverse, which CloudKit requires. No schema change is needed — this is why the day-one design holds. Document in ADR-0011.
